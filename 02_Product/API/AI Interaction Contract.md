# AI Interaction Contract

## Главный принцип

AI в Inspirella — это слой поддержки понимания и объяснения. Он не должен быть единственным источником фактов, автоматически придумывать учреждения или уверенно советовать на основании непроверенных данных.

Первичный порядок:

1. валидировать профиль и запрос;
2. получить подходящие структурированные записи;
3. применить детерминированные правила и trust-фильтры;
4. передать AI только разрешённый контекст;
5. проверить формат и groundedness ответа;
6. показать пользователю происхождение данных, ограничения и следующий шаг.

## Входной контекст

Минимальный вход для MVP:

```json
{
  "language": "en",
  "interests": ["academic", "tech"],
  "goals": ["study_active"],
  "currentStage": "stage_university",
  "preferredCanton": "Zurich",
  "targetLanguageRegion": "de",
  "candidateIds": ["institution-id", "program-id"]
}
```

Не передавать AI секреты, access tokens, пароли, полные внутренние записи пользователей или поля, не нужные для конкретного решения.

## Разрешённый результат

AI может:

- объяснить, почему структурированная рекомендация соответствует профилю;
- превратить несколько проверенных фактов в понятный текст;
- предложить вопросы для дальнейшего уточнения;
- сформулировать реалистичные следующие шаги;
- отвечать на языке пользователя при сохранении смысла исходных данных.

AI не может без проверки:

- утверждать, что программа существует или принимает заявки;
- придумывать сроки, стоимость, зарплаты, требования или контакты;
- заменять official source;
- ставить диагнозы, определять психотип как факт или обещать успех;
- скрывать uncertainty и provisional status.

## Формат ответа

Рекомендуемый продуктовый ответ — JSON с полями `summary`, `whyItFits`, `nextSteps`, `evidence`, `limitations` и `language`. Поля должны быть ограничены схемой и проходить runtime validation. Если ответ невалиден, используется безопасный шаблон без выдуманных деталей.

## Grounding

Каждый факт, который может повлиять на решение, должен быть связан с `sourceId` или с идентификатором записи, из которой он взят. Если доказательства нет, текст должен использовать формулировки вроде «проверьте», «может подойти для изучения» или «данных недостаточно».

## Данные и приватность

- Профиль пользователя используется только для персонализации его опыта.
- Не отправлять в prompt лишние персональные данные.
- Не логировать prompt и ответ с email, токенами или чувствительными атрибутами.
- Не помещать секреты в Markdown-документы, Git или prompt.
- Для подростков использовать поддерживающий, неоценивающий язык.

## Текущее состояние

В `server.ts` уже есть Gemini endpoint со структурированным JSON-запросом и fallback. При дальнейшем подключении нужно не просто «включить AI», а связать ответ с canonical data и добавить schema validation, rate limiting, безопасные логи и тесты на hallucination/invalid JSON.
