# Changelog

## Зачем нужен этот файл

`Changelog.md` фиксирует **что изменилось** — по датам, коротко, по-человечески.
Это не замена `git log`: сюда попадают только изменения, о которых стоит помнить при следующей сессии (новый слой кода, смена архитектурного подхода, крупная чистка, важный документ).

Причины и обоснования решений — в `Decisions.md`, не здесь.

```
## YYYY-MM-DD — короткий заголовок
- что изменилось;
- зачем (1 строка, если не очевидно);
```

## 2026-09-14 — Карта: зум приближал не туда + вся старая колонка logo_url оказалась битой

Sofiia заметила два бага после предыдущей правки: (1) клик по точке на карте иногда визуально отдалял вид вместо приближения; (2) у ETH Zürich (и, как выяснилось, почти у всех остальных) фото не грузится.

- **Зум карты**: `flyTo` использовал фиксированный `zoom: 9.5` — если пользователь уже был приближен сильнее (запросто, обычное поведение), клик по точке визуально ОТДАЛЯЛ вид. Поднято до 16 (глубже порога появления 3D-зданий, 14.5) — клик по точке теперь всегда приближает к самому зданию.

- **Критическая находка по фото**: проверила напрямую все существующие значения `institutions.logo_url` (были у ~76 из 114 изначальных записей, ещё до моих правок) — **абсолютно все были битыми**. Три категории: (1) ~45 записей — буквально строка `\1/favicon.ico`, незаменённый плейсхолдер регулярного выражения из какого-то старого скрипта импорта; (2) ~10 записей — прямые ссылки на logo.svg/png с сайтов самих вузов (как у ETH), заблокированные по хотлинку или просто несуществующие (404); (3) ~12 записей — ссылки вида "правильного" Wikimedia Commons URL с правдоподобным именем файла, но при проверке — тоже 404, то есть, похоже, кем-то (или чем-то) **выдуманные**, не взятые с реального Commons. Это именно то, от чего должен защищать принцип "никогда не выдумывать данные" — и он был нарушен ещё до моего подключения к проекту.
  - Все 76 битых значений очищены (`NULL` вместо мусора — честное отсутствие фото, не битая иконка).
  - ETH Zürich получил настоящее фото с Wikimedia Commons (Hauptgebäude, CC0), проверено напрямую перед записью.
  - Впредь: **каждое фото, которое попадает в БД, проверяется прямым HTTP-запросом перед записью** — не полагаться на правдоподобно выглядящий URL.

## 2026-09-14 — Hero, раунд 5 (финал): 3D-модель феникса полностью работает

Закрыт долгий саг с обрезкой 3D-модели феникса в hero. По порядку реальных причин (не все версии по пути были верными — фиксирую, чтобы не наступать на те же грабли повторно):

1. **Реальный баг**: неверное имя DOM-события (`load` вместо `load-complete`) — уже было исправлено в раунде 4.
2. **Ложный след**: `overflow-hidden` в CSS-обёртках — убраны, но на сам крой не повлияли (canvas физически не может показать больше, чем в нём отрисовано; это стало понятно только постфактум).
3. **Реальный частичный фикс**: hero-секция была зажата в `max-w-6xl` (1152px) общего контейнера страницы — вынесена в full-bleed (на всю ширину экрана), это убрало обрезку по бокам/свечения.
4. **Реальный баг**: `scene.splinecode` на CDN Spline отдаётся без `Cache-Control`/`ETag` — браузер эвристически кэшировал старую версию файла, из-за чего правки Sofiia в Spline визуально не долетали до сайта, сколько бы раз она ни публиковала заново. Исправлено версионированием ссылки (`SPLINE_SCENE_VERSION` в `SplineHero.tsx`, бампается вручную при каждой новой публикации сцены).
5. **Финальная причина**: зум/расстояние камеры в самой сцене Spline — вертикальный угол обзора камеры фиксирован и не зависит от размеров/пропорций нашего контейнера никаким образом; это можно поправить только внутри Spline. Sofiia отодвинула камеру — модель теперь отображается полностью, без обрезки.

Hero-секция считается завершённой. Следующий шаг — перенести тот же визуальный стиль (свечение + сеть) на остальные разделы сайта, умеренно.
