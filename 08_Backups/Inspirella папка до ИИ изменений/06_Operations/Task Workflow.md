# Task Workflow

## Зачем нужен этот файл

Этот файл нужен для того, чтобы зафиксировать, как именно задача должна жить внутри Inspirella.

Если `Processes.md` отвечает на вопрос:

> как в проекте в целом устроено движение работы,

то `Task Workflow.md` отвечает на более практичный вопрос:

> какой путь проходит конкретная задача от появления до завершения.

Этот файл нужен для того, чтобы:
- не превращать список задач в склад мыслей;
- понимать, когда задача действительно готова к работе, а когда ещё нет;
- снижать хаос в приоритетах;
- не держать слишком много ложных `in progress` задач;
- помогать Sofiia и будущим ИИ-агентам одинаково понимать рабочий цикл задачи.

# Главная идея task workflow Inspirella

Inspirella не должна жить по логике:

> появилась идея → сразу стала задачей → потом неделями висит в работе без ясности.

Правильная логика такая:

> каждая задача должна проходить понятный маршрут, где видно, на каком она этапе, что с ней уже сделано, что мешает двигаться дальше и когда она действительно считается завершённой.

Для Inspirella это особенно важно, потому что проект одновременно растёт как:
- продукт;
- data system;
- кодовая база;
- knowledge architecture;
- будущая среда для 1–3 сильных ИИ-агентов.

Без ясного task workflow список задач быстро начинает создавать ложное ощущение движения без реального прогресса.

# Что в Inspirella считается задачей

Задача в Inspirella — это не любая случайная мысль, а оформленный блок работы, у которого есть:
- понятная цель;
- смысл для проекта;
- достаточная ясность для старта или для осознанного ожидания;
- ожидаемый результат.

Задачей может быть:
- документ;
- продуктовая функция;
- data-layer блок;
- исследование;
- архитектурное решение;
- технический cleanup;
- operational change.

Коротко:

> задача — это управляемая единица реальной работы, а не просто записанная идея.

# Основные стадии жизни задачи

Ниже — каноническая цепочка движения задачи в Inspirella.

## Stage 1. Capture

На этом этапе появляется:
- идея;
- наблюдение;
- проблема;
- новая возможность;
- необходимость что-то улучшить.

### Главная цель этапа
Не потерять мысль, но и не делать вид, что она уже готова к немедленной работе.

### Результат этапа
Есть зафиксированная заготовка будущей задачи или направления.

## Stage 2. Clarify

На этом этапе идея уточняется.

Нужно понять:
- что именно нужно сделать;
- зачем это нужно;
- к какому слою проекта это относится;
- какой будет признак хорошего результата;
- достаточно ли информации для продолжения.

### Главная цель этапа
Перевести размытое намерение в понятную формулировку.

### Результат этапа
Появляется задача, которую уже можно оценивать и структурировать.

## Stage 3. Structure

На этом этапе задача получает рабочую форму.

У неё появляются:
- нормальное название;
- описание цели;
- критерии приёмки;
- при необходимости подзадачи;
- при необходимости связи с документами, данными или другими задачами.

### Главная цель этапа
Сделать задачу достаточно понятной, чтобы её можно было безопасно брать в работу.

### Результат этапа
Задача уже не является просто мыслью — она становится рабочим объектом.

## Stage 4. Prioritize

На этом этапе определяется:
- насколько задача важна;
- насколько она срочна;
- усиливает ли она ядро Inspirella;
- стоит ли её делать сейчас или позже.

### Главная цель этапа
Не позволять списку задач расползаться в равномерный шум, где всё кажется одинаково важным.

### Результат этапа
Задача получает своё место в общей логике проекта.

## Stage 5. Activate

На этом этапе задача осознанно переводится в активную работу.

### Важный принцип

Не каждая оформленная задача должна сразу становиться `in progress`.

Активировать стоит только те задачи, по которым:
- есть ресурс внимания;
- есть достаточная ясность;
- есть смысл двигать их именно сейчас.

### Главная цель этапа
Сделать активную работу честной, а не декоративной.

### Результат этапа
Задача реально входит в рабочий фокус.

## Stage 6. Execute

На этом этапе задача реально выполняется.

Это может включать:
- написание документа;
- изменение кода;
- пересборку структуры;
- data-layer работу;
- проектирование логики;
- UX/UI проработку.

### Главная цель этапа
Двигать задачу последовательно, не расползаясь бесконтрольно в соседние блоки.

### Важный принцип

Если по ходу работы выясняется, что задача на самом деле содержит несколько разных задач, лучше честно её разделить, чем притворяться, что это всё один блок.

### Результат этапа
Появляется реальный черновой или почти готовый результат.

## Stage 7. Review

На этом этапе работа пересматривается.

Нужно проверить:
- достигнута ли цель задачи;
- нет ли явных противоречий;
- соответствует ли результат Definition of Done;
- не остались ли скрытые проблемы;
- можно ли считать результат usable для следующего шага.

### Главная цель этапа
Не перепутать «почти готово» с действительно завершённой задачей.

### Результат этапа
Задача либо идёт к закрытию, либо возвращается в работу.

## Stage 8. Close

На этом этапе задача честно закрывается.

### Когда это допустимо
Только если:
- результат реально существует;
- он понятен;
- он проверен на разумном уровне;
- он не требует немедленного возвращения из-за явной незавершённости.

### Главная цель этапа
Сделать закрытие задачи правдивым индикатором прогресса, а не формальным действием.

### Результат этапа
Задача становится завершённой частью развития проекта.

# Рекомендуемые статусы задачи в Inspirella

На текущем этапе для Inspirella особенно важно, чтобы статусы отражали реальность.

## 1. To Do

### Что это значит
Задача оформлена, но ещё не взята в активную работу.

### Когда использовать
- задача понятна;
- она имеет смысл;
- но сейчас не находится в фокусе.

## 2. In Progress

### Что это значит
По задаче реально ведётся работа прямо сейчас.

### Когда использовать
- задача действительно движется;
- по ней есть активное внимание;
- она не просто «важная», а именно в работе.

### Когда не использовать
- если задача просто ждёт будущего времени;
- если по ней давно нет движения;
- если она слишком размыта для реального старта.

## 3. Review / Check Needed

Если later в системе появится отдельный статус, он может быть очень полезен.

### Что это значит
Работа уже сделана, но требует осмысленной проверки перед окончательным закрытием.

### Почему это полезно
Это уменьшает давление закрывать всё сразу либо держать всё слишком долго в `in progress`.

## 4. Complete / Done

### Что это значит
Результат действительно завершён на уровне, который сейчас нужен проекту.

## 5. On Hold / Paused

Если later будет нужно отдельное состояние, оно тоже может быть полезным.

### Что это значит
Задача не отменена, но сознательно приостановлена.

### Почему это полезно
Это честнее, чем держать такие задачи бесконечно в `in progress`.

# Когда задачу можно переводить в `In Progress`

Это один из самых важных operational-вопросов.

Задачу стоит переводить в активную работу, если:
- понятна цель;
- достаточно ясен результат;
- нет критичной нехватки контекста;
- есть пространство внимания на её выполнение;
- она действительно является актуальным приоритетом.

## Не стоит переводить задачу в `In Progress`, если:
- она ещё слишком сырая;
- она зависит от незакрытого предыдущего блока;
- по ней пока не планируется реальное движение;
- она просто кажется важной, но не находится в фокусе.

# Когда задачу стоит дробить на подзадачи

Задачу стоит дробить, если:
- внутри неё больше одного ясного блока работы;
- разные части можно сделать независимо;
- нужен отдельный контроль прогресса;
- без дробления задача становится слишком большой и расплывчатой.

## Особенно хорошо дробить, когда есть
- документ + код;
- data model + validation + import;
- feature design + implementation + review;
- product block с несколькими независимыми шагами.

## Не нужно дробить ради дробления

Если подзадачи не добавляют ясности и только создают шум, лучше оставить более компактную структуру.

# Когда задачу стоит вернуть назад, а не закрывать

Иногда задача внешне выглядит почти готовой, но её лучше вернуть назад в работу или review, чем закрывать.

Это стоит делать, если:
- цель формально закрыта, но результат слишком сырой;
- обнаружилось важное противоречие;
- работа не прошла проверку;
- задача фактически привела к новому сильному разветвлению, которое нельзя игнорировать;
- результат нельзя безопасно использовать как следующий шаг.

# Что особенно важно для task workflow Inspirella сейчас

На текущем этапе проекта особенно важно:

## 1. Не держать слишком много активных задач одновременно

Слишком много `in progress` почти всегда означает потерю реального фокуса.

## 2. Делать задачи достаточно конкретными

Это особенно важно, потому что сейчас строится основа проекта:
- документы;
- data-layer;
- development rules;
- operations.

## 3. Поддерживать честное соответствие между реальной работой и ClickUp

Список задач должен отражать правду, а не только намерения.

## 4. Видеть разницу между мыслью, блоком, задачей и активной задачей

Именно это сильно уменьшает хаос.

# Как future AI-agents должны работать с задачами

Будущие ИИ-агенты должны быть встроены в task workflow, а не обходить его.

## 1. Агент не должен превращать каждую идею в активную задачу

Сначала нужна ясность, потом структура, потом приоритет.

## 2. Агент должен помогать уточнять задачу до старта

Это одна из самых полезных ролей ИИ в Inspirella.

## 3. Агент не должен оставлять задачу в ложном `in progress`

Если реального движения нет, это лучше честно отразить.

## 4. Агент должен уметь видеть, когда задачу лучше разделить

Это особенно важно в больших смысловых блоках.

## 5. Агент должен уважать Definition of Done

Нельзя закрывать задачу просто потому, что что-то было создано.

# Task workflow и миссия Inspirella

Для Inspirella task workflow — это не просто управление задачами ради порядка.

Это один из способов сделать большой проект устойчивым.

Потому что проект с такой амбицией не может двигаться только на вдохновении и случайных импульсах. Ему нужен рабочий ритм, в котором:
- идеи не теряются;
- важное не тонет в шуме;
- активная работа действительно движется;
- завершённость что-то реально означает.

Хороший task workflow помогает превращать vision Inspirella в последовательную, реальную систему движения вперёд.
